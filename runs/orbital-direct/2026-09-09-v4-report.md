# Pilot A v4 — verification pipeline and real extractor validation

_Orbital Direct · 2026-09-09 · `npm run pilot-a-v4`, `npm run fidelity`_

---

## The environment constraint, stated first

**Page retrieval is blocked.** The egress gateway returns 403 to `CONNECT` for
every host tested — `gov.uk`, `knittingindustry.com`, `r.jina.ai` — from both
the Node process and the agent's own fetch tool. **No LLM API key exists.**

So two things below are real and one is not:

| | Status |
|---|---|
| Extractor logic, schema, coercion, validation, promotion | **Real** — exercised by actual model output |
| Verification mechanism: retrieval → passage match → level → score | **Real code, fixture input** |
| Live verification against real pages | **NOT VALIDATED** |

The reconstructed pages in `fixtures/reconstructed-pages.ts` are search snippets
wrapped in a body. They exercise the mechanism. They are not retrieved pages,
and a passage match against them is close to circular because the passage came
from the same snippet. **This is not live verification and must not be reported
as such.**

## 1. Real ClaimExtractor validation

Five cases, real Pilot A sources, `EXTRACTION_SYSTEM_PROMPT` verbatim, real
model output recorded and replayed through `LlmClaimExtractor` — so parsing,
coercion, schema validation and promotion all ran on genuine output. Only the
HTTP transport was substituted.

**7 claims across 5 cases. 0 discarded by schema validation. 0 fidelity
findings.**

Every claim carried: attribution attributes, claim text, source URL, source
type, dates where stated, geography, industry, evidence passage, confidence,
topic. Polarity and rationale came separately, as judgement.

The case that matters most is `brambles-collision`. Asked about Bramble Group,
handed a page about Brambles Ltd of Australia, the extractor reported
`statedName: "Brambles Ltd"`, `country: "Australia"`, `industry: "pallet
pooling"`. It did not decide the source was irrelevant and it did not claim it
was the target — it reported what the source said and left the engine to reach
`identity_collision`. **The extractor stayed an extractor.**

Two cases test date discipline. Neither Maeving snippet states a date (the MCN
URL contains "2026/august", which is not the same thing) and the extractor
emitted no `eventDate`. The Bramble snippet does state 31 July 2026, and it was
reported. Correct on both.

**Honest caveat: 5/5 with zero findings is weak evidence.** The same model
produced the extractions and the gold standards. A self-graded exam.

## 2. Extraction fidelity measurement

Because the self-assessment proves little, the **instrument** was validated
instead, on adversarial input. All ten categories are caught:

| Category | Caught |
|---|---|
| missing identity attributes | ✓ |
| incorrect geography | ✓ |
| incorrect company attribution | ✓ |
| incorrect dates (including a date no source states) | ✓ |
| unsupported polarity | ✓ |
| polarity contradiction | ✓ |
| hallucinated claims (invented figures, invented URLs, excess claims) | ✓ |
| evidence passage not supporting the claim | ✓ |
| topic misclassification | ✓ |
| interpretation not extraction (geography imported from the target) | ✓ |

Nothing is repaired. Every finding is recorded with the claim id and the detail.

## 3. Verification pipeline

Implemented: `PageRetriever` (interface), `HttpPageRetriever` (real, injected
fetch), `NullPageRetriever` (declares itself blocked), `FixturePageRetriever`.
Plus text extraction, content hashing, and `passageSupportedByPage` — verbatim
match first, then distinctive-token overlap at a 75% threshold.

The rule the pipeline enforces: **a claim reaches `page_retrieved` only if the
page was fetched AND its supporting passage was found in the body.** Retrieval
alone is not enough. A page that comes back without the passage stays at
snippet level with the mismatch recorded — that is the check that would catch a
paraphrase gone too far, or an invented passage.

`Verification` is now `page_retrieved | search_snippet` rather than the old
`sources_opened | search_summary_only`, so the distinction is explicit in the
type system and the engine cannot conflate them.

## 5. Score distribution — the answer to the ceiling question

| Run | n | min | max | spread | mean | scores |
|---|---|---|---|---|---|---|
| A unverified | 4 | 68 | 70 | **2** | 69.5 | 70, 70, 70, 68 |
| B reconstructed | 4 | 69 | 78 | **9** | 74.5 | 78, 77, 74, 69 |
| raw (uncapped) | 4 | 78 | 88 | 10 | — | 88, 87, 84, 79 |

**Removing the ceiling produces real differentiation — a 2-point spread becomes
9.** Three of four rows were pinned to exactly 70 by the cap, which is not a
ranking; underneath, the same rows differ by 10 raw points.

**The scoring model was not changed to achieve this.** The only movement in raw
score is +1 per row, from the single verification point already in the evidence
component. Everything else came from caps ceasing to apply because evidence
earned page level. Classification changed accordingly: Maeving and Baltex reach
`CONFIRMED_OPPORTUNITY`, Maeving reaches High confidence, and the recommended
action moves from `research_further` to `draft_outreach` — correctly, because
the evidence is now verified.

Baltex reaches 77 but stays at Medium confidence: one independent source
(the syndicated HSBC release). That is the independence rule holding
even as the verification cap lifts, which is the behaviour we want.

## 6. The commercial reasoning chain

Maeving, the strongest row, end to end:

**FACT** — "Maeving secured a £3m trade finance facility from HSBC UK, backed
by UK Export Finance, to invest in production capacity for demand in the US,
Germany and France, creating 13 new jobs at Coventry." (gov.uk, tier 2,
2026-08-15, identity: match, 3 attributes corroborating)

**FACT** — "Maeving began exporting to California, Germany and France in 2023,
exports around half its bikes, and US sales have risen fivefold this year."
(motorcyclenews.com, tier 3, 2026-08-15)

**INFERENCE** — consignment volume on established US and European lanes is
rising steeply, with funded capacity behind it and tariff friction to manage.
*Because the company reports the fivefold increase itself and the facility funds
the capacity to serve it.*

**HYPOTHESIS** (unproven) — freight arrangements sized for 2023-era volumes are
carrying several times that, on a regulated cargo type, in a tariff
environment — which is when rates, consolidation and DG documentation get
reopened. *Test: ask whether the current US arrangement was priced before the
fivefold increase, and who handles the Class 9 paperwork.*

**CLIENT RELEVANCE** — Coventry manufacturer of physical goods, exporting
around half its output, scaling on funded capacity.

**CONSEQUENCE** — more cross-border consignments and more Class 9 documentation
to produce.

**ACTION** — draft outreach. "Your US sales are up fivefold and you've just
funded the capacity to go further. Worth checking whether your shipping was
priced for 2023 volumes or today's — and we can look at the Class 9 battery
documentation while we're there."

Would a salesperson understand why to call? Yes — and the mechanism is specific:
*volume on a named lane multiplied, funding committed, cargo type regulated*.
Not "this may create logistics opportunities". Fact, inference and hypothesis
stay visibly separate, and the hypothesis is labelled unproven with the question
that would settle it.

## 7. Signal architecture and hiring

No hiring feature was built. The architecture already accommodates it without
change: `trigger` is a free string, `ClaimTopic` includes `hiring`, five
recruitment sources are registered as authoritative for hiring claims and
weak elsewhere, and polarity plus commercial consequence are judged per client
rather than per signal type. Adding hiring means adding a demand trigger to a
client profile and a query — no engine change.

The abstraction is "what changed, and does that change create an actionable
commercial consequence for this client?" — which is why contraction is a
first-class outcome rather than an absence of signal.

## 8. Remaining failure modes

1. **Live verification is unvalidated.** The single most important gap. Real
   retrieval would test whether extracted passages survive contact with real
   pages — including boilerplate, paywalls, JavaScript rendering and redirects.
   None of that is exercised.
2. **Extractor fidelity is self-assessed.** The instrument is validated; the
   extractor's real-world accuracy is not. A different model, or this model on
   unfamiliar sources, could score very differently.
3. **The passage-match threshold (75% token overlap) is untuned.** Chosen by
   judgement, never calibrated against real pages, and it sits directly on the
   path that lifts the cap. Too low and invented passages pass; too high and
   honest paraphrase fails.
4. **Topic assignment remains unvalidated** — a mislabelled topic silently
   changes the tier a claim scores at.
5. **Polarity validation is lexical** and will miss euphemism.
6. **Reconstructed-page verification is close to circular** and must never be
   cited as evidence that claims are true.
7. **Registry coverage is still partial** at 89 entries.
